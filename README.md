# camera_live

Локальный веб-стрим USB-камеры Windows-ноутбука для прототипов Virtual Inspection Lab (VIL).

**Архитектура:** USB/UVC camera -> OpenCV on Windows -> MJPEG over HTTP -> web browser. Приложение захватывает **физическую камеру ноутбука**, а не камеру компьютера зрителя. Камера и сервер должны быть запущены на одном Windows-ноутбуке.

## Быстрый запуск (Windows 10/11)

1. Подключите USB-камеру, проверьте её в приложении «Камера» Windows и закройте другие приложения, использующие устройство.
2. Установите Python 3.11/3.12/3.13 (с добавлением в PATH) и Git.
3. Выполните в PowerShell:

```powershell
git clone https://github.com/amba-pro/camera_live.git
cd camera_live
.\start_windows.bat
```

Скрипт создаст `.venv`, установит зависимости и запустит веб-сервер. В браузере на **этом же ноутбуке** откройте **http://127.0.0.1:8000**.

Можно также вручную запустить:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe camera_live.py --camera 0 --width 1280 --height 720 --fps 15
```

Если нужная камера не индекс 0:

```powershell
.\.venv\Scripts\python.exe camera_live.py --list-cameras
.\.venv\Scripts\python.exe camera_live.py --camera 1
```

Без `--camera` на Windows выбирается подключённая Logitech (например, `HD Pro Webcam C920`), а не встроенная камера ноутбука. Встроенная камера здесь — индекс `0`, Logitech C920 — индекс `1`. Синий ободок загорается у C920, когда захват идёт именно с неё.

```powershell
.\.venv\Scripts\python.exe camera_live.py --camera-name C920
.\.venv\Scripts\python.exe camera_live.py --camera 0
```

Для Windows можно явно выбрать backend: `--backend dshow` или `--backend msmf`. По умолчанию `auto` пробует DirectShow, затем Media Foundation.

Если открыта встроенная камера и кадр почти чёрный, на странице появляется предупреждение про шторку. Для Logitech это не нужно: перезапустите сервер без `--camera 0`.

## Просмотр с другого устройства по Wi-Fi / LAN

На ноутбуке запустите:

```powershell
.\start_windows.bat --host 0.0.0.0
```

Страница и консоль показывают адрес физического адаптера (Wi-Fi или Ethernet) и имя Wi-Fi. Адреса VPN, TAP, Tailscale и других виртуальных адаптеров не показываются: с телефона они не открываются. Телефон должен быть в той же Wi-Fi-сети, не в мобильном интернете. Откройте `http://<IPv4-НОУТБУКА>:8000`. Если браузер не соединяется, разрешите входящие TCP-подключения на порт 8000 в брандмауэре Windows **только для частной сети**.

**Безопасность:** встроенный сервер не содержит авторизации, не использует HTTPS и не предназначен для публикации в интернете. **Не делайте port forwarding / не открывайте порт 8000 в публичный интернет.** Для доступа извне используйте защищённую частную сеть (например, Tailscale с ограничением доступа к устройству) либо отдельный HTTPS reverse proxy с аутентификацией. Не публикуйте адрес камеры в общедоступном GitHub.

## Параметры

| Ключ | По умолчанию | Назначение |
| --- | --- | --- |
| `--camera` | авто: Logitech/C920, иначе `0` | Индекс OpenCV. `0` на этом ноутбуке — встроенная камера |
| `--camera-name` | — | Часть имени DirectShow, например `C920` |
| `--list-cameras` | — | Проверить индексы 0–5 и завершиться |
| `--host` | `127.0.0.1` | Только локально; `0.0.0.0` для LAN |
| `--port` | `8000` | HTTP-порт |
| `--width` / `--height` | `1280` / `720` | Желаемое разрешение |
| `--fps` | `15` | Предел отправляемых кадров/сек |
| `--jpeg-quality` | `75` | JPEG quality 40–95 |
| `--backend` | `auto` | `auto`, `dshow`, `msmf`, `any` |

Реальные FPS и разрешение зависят от камеры, драйвера, USB-канала и системы. MJPEG удобен для первого рабочего прототипа; WebRTC/H.264 лучше подходит для многих удалённых зрителей и экономии трафика.

## HTTP endpoints

- `/` — веб-интерфейс с видеопотоком и статусом
- `/stream.mjpg` — непрерывный MJPEG-поток для `<img>` и VLC
- `/snapshot.jpg` — последний свежий кадр JPEG
- `/api/status` — JSON с состоянием устройства, разрешением, FPS и полем `notice`, если кадр почти чёрный

Когда камера временно недоступна, сервер не должен падать: запускается повторное подключение. Статус и причина ошибки видны в веб-интерфейсе.

## Ограничения и проверка

Это **не** облачный хостинг GitHub Pages. GitHub хранит код; стрим работает, пока запущен `camera_live.py` на ноутбуке с камерой.

Локальные автоматические проверки (без камеры):

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

### Что показала проверка на Windows 10 (22 октября 2026)

Подключены две камеры. Индекс `0` — встроенная `USB2.0 HD UVC WebCam` (Sonix). Она даёт почти чёрный кадр, и синий ободок при этом не загорается. Нужная USB-камера — **Logitech HD Pro Webcam C920**, индекс `1`, DirectShow.

| Параметр | Logitech C920 |
| --- | --- |
| Индекс | `1` |
| Backend | `dshow` |
| Python / OpenCV | 3.13.12 / 4.14.0 |
| Разрешение | 1280×720 |
| Формат | YUY2, около 8 FPS на 720p |
| Картинка | Обычная сцена комнаты, не чёрный кадр |

Разрешение Windows «Конфиденциальность → Камера» для классических приложений было **Allow**. Другие приложения камеру в момент проверки не занимали.

Ctrl+C завершает процесс с кодом 0, печатает «Остановка...» и отпускает камеру: сразу после этого устройство снова открывается. На этом драйвере второй `VideoCapture` не блокирует первый — сервер всё равно получает кадры. Отдельной ошибки «камера занята» на этом устройстве не возникало.

Не проверено на этом ноутбуке:

- Физическое отключение USB. Программное отключение устройства требует прав администратора и завершилось отказом, поэтому автоматическое восстановление после unplug подтверждено тестом с имитацией обрыва кадров, а не выдёргиванием кабеля.
- Просмотр с телефона. Адрес `192.168.50.7` оказался TAP-Windows (VPN), а не сетью телефона. Рабочий адрес ноутбука — Wi-Fi. Входящее правило брандмауэра отдельно не создавалось: для `python.exe` уже разрешён входящий TCP на частном и публичном профилях. Соединения с телефона в журнале сервера не было.

Перед `--host 0.0.0.0` проверьте профиль сети:

```powershell
Get-NetConnectionProfile
```

Правило только для частного профиля, и только если зритель действительно в доверенной LAN:

```powershell
New-NetFirewallRule -DisplayName "camera_live private" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8000 -Profile Private
```

Не добавляйте это правило для профиля Public и не делайте port forwarding.

При отсутствии видео: проверьте шторку, настройки Windows «Конфиденциальность и безопасность → Камера → Разрешить классическим приложениям доступ», индекс `--camera`, свободно ли устройство, USB-порт и `--backend dshow` / `msmf`. `start_windows.bat` переключает консоль в UTF-8, чтобы русские сообщения не превращались в кракозябры.

Проект можно интегрировать в VIL как транспорт для наблюдения; аналитика CV и запись потока здесь намеренно не включены.
