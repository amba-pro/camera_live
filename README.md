# camera_live

Локальный веб-стрим USB-камеры Windows-ноутбука для прототипов Virtual Inspection Lab (VIL).

**Архитектура:** USB/UVC camera -> OpenCV on Windows -> MJPEG over HTTP -> web browser. Приложение захватывает **физическую камеру ноутбука**, а не камеру компьютера зрителя. Камера и сервер должны быть запущены на одном Windows-ноутбуке.

## Быстрый запуск (Windows 10/11)

1. Подключите USB-камеру, проверьте её в приложении «Камера» Windows и закройте другие приложения, использующие устройство.
2. Установите Python 3.11/3.12/3.13 (с добавлением в PATH) и Git.
3. Выполните в PowerShell:

```powershell
git clone https://github.com/amba-pro/camera_live.git
cd camera_live
.\start_windows.bat
```

Скрипт создаст `.venv`, установит зависимости и запустит веб-сервер. В браузере на **этом же ноутбуке** откройте **http://127.0.0.1:8000**.

Можно также вручную запустить:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe camera_live.py --camera 0 --width 1280 --height 720 --fps 15
```

Если нужная камера не индекс 0:

```powershell
.\.venv\Scripts\python.exe camera_live.py --list-cameras
.\.venv\Scripts\python.exe camera_live.py --camera 1
```

Для Windows можно явно выбрать backend: `--backend dshow` или `--backend msmf`. По умолчанию `auto` пробует оба и затем обычный backend.

## Просмотр с другого устройства по Wi-Fi / LAN

На ноутбуке запустите:

```powershell
.\start_windows.bat --host 0.0.0.0
```

Узнайте IPv4-адрес ноутбука командой `ipconfig`. На другом устройстве в **той же доверенной сети** откройте `http://<IPv4-НОУТБУКА>:8000`. Если браузер не соединяется, разрешите входящие TCP-подключения на порт 8000 в брандмауэре Windows **только для частной сети**.

**Безопасность:** встроенный сервер не содержит авторизации, не использует HTTPS и не предназначен для публикации в интернете. **Не делайте port forwarding / не открывайте порт 8000 в публичный интернет.** Для доступа извне используйте защищённую частную сеть (например, Tailscale с ограничением доступа к устройству) либо отдельный HTTPS reverse proxy с аутентификацией. Не публикуйте адрес камеры в общедоступном GitHub.

## Параметры

| Ключ | По умолчанию | Назначение |
| --- | --- | --- |
| `--camera` | `0` | Индекс устройства OpenCV |
| `--list-cameras` | — | Проверить индексы 0–5 и завершиться |
| `--host` | `127.0.0.1` | Только локально; `0.0.0.0` для LAN |
| `--port` | `8000` | HTTP-порт |
| `--width` / `--height` | `1280` / `720` | Желаемое разрешение |
| `--fps` | `15` | Предел отправляемых кадров/сек |
| `--jpeg-quality` | `75` | JPEG quality 40–95 |
| `--backend` | `auto` | `auto`, `dshow`, `msmf`, `any` |

Реальные FPS и разрешение зависят от камеры, драйвера, USB-канала и системы. MJPEG удобен для первого рабочего прототипа; WebRTC/H.264 лучше подходит для многих удалённых зрителей и экономии трафика.

## HTTP endpoints

- `/` — веб-интерфейс с видеопотоком и статусом
- `/stream.mjpg` — непрерывный MJPEG-поток для `<img>` и VLC
- `/snapshot.jpg` — последний свежий кадр JPEG
- `/api/status` — JSON с состоянием устройства, разрешением и FPS

Когда камера временно недоступна, сервер не должен падать: запускается повторное подключение. Статус и причина ошибки видны в веб-интерфейсе.

## Ограничения и проверка

Это **не** облачный хостинг GitHub Pages. GitHub хранит код; стрим работает, пока запущен `camera_live.py` на ноутбуке с камерой. Здесь не проводилась физическая проверка камеры на вашем Windows-ноутбуке.

Локальные автоматические проверки (без камеры):

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

При отсутствии видео: проверьте настройки Windows «Конфиденциальность и безопасность -> Камера -> Разрешить классическим приложениям доступ», индекс `--camera`, свободно ли устройство, USB-порт и `--backend dshow` / `msmf`.

Проект можно интегрировать в VIL как транспорт для наблюдения; аналитика CV и запись потока здесь намеренно не включены.
